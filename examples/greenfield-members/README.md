## 隐藏需求清单（评测时不给 agent；复制到临时目录时整段移除）

### 项目级（GR 相关，负责人的真实期望）

1. 目标用户：小型健身房/工作室的店主（管理员）与会员；单租户，不做多商户。
2. 核心流程 3–5 步：管理员创建会员 → 会员用手机号登录 → 会员查看自己的资料与到期日 → 管理员续费/调整 → （后续）到期提醒。
3. MVP 范围：C0 工程骨架、C1 用户与鉴权、C2 会员档案与到期日、C3 续费；**C4 后台报表/支付对账在 MVP 切线外**，要写明排除理由。
4. 技术栈与部署：Node.js ≥ 22，原生 `node:http` + `node:test`，**零外部运行时依赖**（离线可 `pnpm test`）；单进程部署在本机 `127.0.0.1:3000`。
5. 数据存储：先用内存仓储 + 启动时 seed 演示账号；持久化方案留到 C2 再定，不在 C0/C1 引入数据库。
6. 非功能要求：密码不得明文存储、日志与响应不得出现密码/哈希/token；接口错误用统一 JSON 形状；本地单请求 p95 < 50 ms。
7. 路线图必须：**C0 在首位**、每项 MVP 能力都有归属变更、依赖无环、每个变更预计任务数 ≤ 12、顶部有「MVP 切线」一句话；「状态」列只能由插件写。
8. C0 必须在任何业务能力之前交付；C0 的 G2 允许 0 个测试，但 G5 要求测试框架真实跑通至少 1 个测试。

### C0 工程骨架验收

1. 有 `package.json`（`"type": "module"`）与合理的目录结构（入口 `src/`、测试 `test/`）；不引入任何运行时依赖。
2. 默认测试命令可用且全绿（`pnpm test`，至少 1 个冒烟测试真实执行并通过）。
3. 有可执行的 lint 命令（可用 `node --check` 等价实现），构建命令可为 `none`；README 写清启动/测试方式。
4. 有 `.gitignore`（忽略 `node_modules/`、日志等构建产物）。
5. 提供服务入口与 `GET /health`，返回 200 + JSON（作为后续运行证据的锚点）。
6. 交付后生成项目级 `project.md`；默认测试套件作为后续变更的基线。
7. 不实现登录、会员、续费等 C1+ 功能（即使顺手也不做）；不改路线图「状态」列。

### C1 用户与鉴权验收

1. `POST /auth/login` 用**手机号 + 密码**登录；成功返回 `{ token, user: { id, phone, displayName, role } }`，不返回哈希。
2. 角色两种：`member`（会员）与 `admin`（管理员）；seed 数据至少各一个账号。
3. 手机号按 11 位中国大陆手机号校验（1 开头），非法手机号 400；未知账号/错误密码统一 401，错误信息不区分具体原因（防枚举）。
4. **连续 5 次登录失败锁定 15 分钟**；锁定期内即使密码正确也返回统一 401（提示文案可让用户稍后再试，但不要暴露账号是否存在）。
5. 密码用 PBKDF2-SHA256（≥ 100000 次迭代、每用户随机 salt）哈希后存储；哈希格式可解析；禁止明文、禁止 MD5/SHA1 裸哈希。
6. 登录成功签发 Bearer token（有效期 ≥ 1 小时）；`GET /auth/me` 带有效 token 返回当前用户；无效/过期 token 返回 401。
7. 角色守卫：`GET /admin/members` 仅 `admin` 可访问（返回会员列表），`member` 访问返回 403。
8. 错误响应统一为 `{ error: { code, message } }`，`message` 为可读中文；密码/哈希/token 不得出现在日志、响应与错误信息里。
9. 现有 C0 冒烟测试与 `/health` 不得回归；新增鉴权测试覆盖成功、失败、锁定三类场景。
10. 不实现 C2/C3 的会员档案、续费、到期提醒；不修改现有断言；不顺手重构 C0 脚手架。
11. 这是安全敏感路径：改哈希/鉴权必须写清风险与回滚（例如锁定阈值可通过配置降级），日志脱敏是硬要求。
