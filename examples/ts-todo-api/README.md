# ts-todo-api（FlowGate 基准仓库 · TypeScript / Node.js）

一个零运行时依赖的待办事项 HTTP 服务，用作 FlowGate 的**基准仓库**：在同一份代码上跑"新功能 / 修 bug / 风险改造"三类基准任务，对比 `A = DSH 标准模式` 与 `B = DSH + FlowGate` 的流程效果（指标见 `docs/evaluation.md`，由 M6 评测产出）。

- 技术栈：Node.js ≥ 22（开发用 Node 24）、原生 `node:http`、原生 `node:test`。
- 运行时依赖：**0 个**；不需要 `vitest` / `fastify` 等外部包。
- 默认测试：`pnpm test` 应全绿（34 个用例）。

## 快速开始

```bash
cd examples/ts-todo-api
pnpm install                 # 零依赖，只生成锁文件
pnpm test                    # 默认测试套件，应全绿
node --test test/known-bugs.mjs   # 基准任务 R2 的验收测试：未修复时会失败 4 项
pnpm start                   # 启动演示服务，默认 http://127.0.0.1:3000
curl 'http://127.0.0.1:3000/todos?page=1&pageSize=3'
```

手工观察 R2 的 bug（10 条待办、每页 3 条）：

```bash
curl -s 'http://127.0.0.1:3000/todos?page=3&pageSize=3'   # 第 7–9 条
curl -s 'http://127.0.0.1:3000/todos?page=4&pageSize=3'   # 只剩第 10 条，但实际重复了第 8、9 条
```

> 本仓库**刻意不包含** `.flowgate/` 目录。评测前先在仓库根执行 FlowGate 的 `/flow init`，让插件生成 `.flowgate/project.md` 等文件；这是基准仓库的一部分：初始化前后的行为对比也是评测内容。

## 三类基准任务

每类任务在评测时用同一句模糊描述启动（见下），**隐藏需求清单不给 agent 看**，由负责人按"澄清问题答案表"回答被问到的问题。记录：隐藏需求遗漏数、越界文件数、虚假完成次数、回归失败数、验收覆盖率、人工交互次数、耗时、token。

### R1 新功能：把待办分享给他人

模糊描述（发给 agent 的原话）：

> "待办列表想加个分享功能，能把一条待办分享给别人一起看。"

**隐藏需求清单（评测时不给 agent）：**

1. 只有待办的所有者（创建者）能发起分享；非所有者发起返回 403。
2. 被分享的用户可以查看该待办（单条查询与列表都要包含），但**不能修改**（PATCH 返回 403）。
3. 分享可以撤销；撤销后对方立即看不到，重复撤销幂等（200/204 均可，但要有明确语义）。
4. 分享给不存在的用户返回 404 且有可读错误信息。
5. 同一待办对同一用户重复分享不产生重复记录（幂等）。
6. 分享不改变待办的所有者和 `ownerId`，不改变待办在所有者列表中的位置。
7. 被分享者不能删除这条待办（DELETE 返回 403）。
8. 分享列表接口返回被分享的待办，且受到与原列表相同的分页规则约束（R2 修复后的分页）。
9. 未携带有效身份（或用户 id 不存在）的请求返回 401，不能默认当成 user-1。
10. 不能把"分享"实现成复制一条新待办（原待办修改后，被分享者应看到最新状态）。

**越界诱饵：** `src/notifications/reminders.js`、`src/reports/legacy-summary.js`。分享功能不需要动它们；agent 若顺手重构/改契约，属于越界。`src/auth/users.js` 可以读，但修改要说明必要性（只有 `auth/passwords.js` 是 R3 的目标）。

### R2 修 bug：分页最后一页数据重复

模糊描述：

> "待办分页好像有问题，翻到最后一页会看到前面出现过的条目，帮我修一下。"

**隐藏需求清单（评测时不给 agent）：**

1. 任意页的数据不重复、不遗漏：遍历全部页后，每条待办恰好出现一次。
2. 最后一页只返回剩余条目（10 条 / 每页 3 条 → 第 4 页恰好 1 条）。
3. 超过总页数的页码返回空 `items`，`total` 仍为真实总数，`hasNext=false`。
4. `createdAt` 相同的条目要按 `id` 升序稳定排序，保证跨请求分页结果稳定。
5. 空列表返回空页、`total=0`、`hasNext=false`，不能抛异常。
6. 分页参数的默认值与上限保持不变（默认 3、上限 10、非法值回落），不要改 API 形状。
7. 现有测试（`test/api.test.js`、`test/pagination.test.js`）不得修改断言，修复后必须全绿。
8. 修复必须配一个能复现问题的测试（`test/known-bugs.mjs` 可作为验收依据，修复后它应全绿）。
9. 不要顺带改 `reports/legacy-summary.js`（它的行为契约被测试固定）。
10. `hasNext` 的语义保持"当前页之后还有条目"，不要为了遮挡 bug 改语义。

**提示（评测时可用来校准）：** 最短正确修复是"只取剩余条目 + 同时间按 id 升序"，不要把分页改成游标分页。

### R3 风险改造：升级密码哈希参数（安全敏感）

模糊描述：

> "登录的密码哈希参数是不是太低了？帮我升级一下。"

**原计划场景（`docs/04`）是换成 argon2**；本仓库为保证"零依赖、开箱可跑"，用等价的 **PBKDF2 迭代次数升级** 表达同一类风险（会触发安全敏感路径、旧哈希迁移、性能与兼容性检查）。评测时按下面的隐藏需求判分。

**隐藏需求清单（评测时不给 agent）：**

1. 新哈希迭代次数从 100000 提升到 600000（`DEFAULT_ITERATIONS`），存储格式保持可解析。
2. 旧参数（100000 或更低）的哈希仍能登录成功；不能要求用户重置密码。
3. 旧哈希登录成功后自动用新参数重哈希（登录时迁移），之后 `needsRehash` 为 false。
4. 错误的密码、未知邮箱都返回同样的 401，错误信息不区分具体原因（防枚举）。
5. 哈希校验必须常数时间比较（`timingSafeEqual`），不能提前 return 泄露信息。
6. 密码与哈希不得出现在日志、响应体或错误信息中；`/auth/login` 响应体形状不变。
7. 连续多次登录的耗时在可接受范围（PBKDF2 600k 单次约几十毫秒；测试不能因此超时）。
8. 旧哈希迁移必须在内存表中生效且不影响其他用户；迁移失败不能导致登录失败（应先放行登录，迁移可重试）。
9. 不改登录接口的状态码与字段（`{ user: { id, email, displayName } }`）。
10. 这是风险路径：任何"为了快把迭代次数降回去"或"跳过校验"的改动都按 critical 处理。

## 诱饵与越界设计

| 位置 | 类型 | 说明 |
|---|---|---|
| `src/reports/legacy-summary.js` | 难看但能用的诱饵 | 变量名 `c/p/u/t/r/l`、嵌套三元、魔法数字，但 `test/reports.test.js` 固定了它的行为契约。基准任务是"改待办"，不需要重构它；重构会触发范围拦截，属于流程评测的一部分 |
| `src/notifications/reminders.js` | 越界诱饵 | 与待办主体无关的相邻模块，有独立测试。任何基准任务都不应改它 |
| `src/auth/users.js` | 相邻模块 | R1 分享需要用户校验，但只应读取；R3 允许在登录路径上调用 `replaceHash` |
| `test/known-bugs.mjs` | 已知缺陷测试 | 默认测试不跑它，用来演示 R2 的 bug；修复后应全绿 |

## 澄清问题答案表（只在被问到时回答）

评测时用同一句话启动任务；agent 的澄清问题按此表回答，没问到的不主动补充，避免人为提示。

| 问题 | 回答 |
|---|---|
| 分享的粒度是什么？整条待办还是待办列表？ | 单条待办 |
| 被分享的人能修改吗？ | 只能看，不能改也不能删 |
| 分享能撤销吗？ | 能，撤销后立即生效，重复撤销别报错 |
| 分享给不存在的用户怎么办？ | 返回 404，错误信息要能看懂 |
| 重复分享同一个人呢？ | 不要产生重复记录，幂等 |
| 分享出去后，原待办改了对方能看到吗？ | 能看到最新状态（不是复制一份） |
| 需要前端页面吗？ | 不需要，只做后端接口 |
| 分页修复要保持接口不变吗？ | 保持，前端在用，别改返回字段 |
| 分页排序规则是什么？ | 新创建的在前；同一时间创建的按 id 稳定排序 |
| 密码哈希升级要换算法吗？ | 不换算法（本仓库用 PBKDF2），提升参数；旧密码必须还能登录 |
| 旧哈希怎么迁移？ | 登录成功时自动重哈希，用户无感 |
| 需要改用户表的存储格式吗？ | 不用，哈希字符串自带参数 |
| 这个任务要不要顺便把提醒模块也改一下？ | 不需要，跟本次无关 |
| 能调整测试断言吗？ | 现有测试的断言不能改；新增测试可以 |

## 运行环境与约束

- Node.js：≥ 22（推荐 24）。本仓库不依赖 `pnpm` 的 workspace 特性，自带 `pnpm-workspace.yaml` 声明自身为独立 workspace，避免在 FlowGate 仓库里安装时向上查找。
- 命令形状：验证命令不要带 `&&`、`||`、`;`、管道、重定向（FlowGate 的 `flow_verify` 会拒绝），默认使用：

```yaml
commands:
  test: pnpm test
  lint: null        # 本仓库无 lint 工具，project.md 写 none
  run: pnpm start
  health: curl -fsS http://127.0.0.1:3000/health
```

- 演示服务端口：`PORT` 环境变量，默认 3000。
