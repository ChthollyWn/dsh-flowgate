  （`startHostPlugin` → `runtime.ensureEngine` → `engine.load()`）不抛错；`/flow doctor`
  可读（初始化/账本/配置正常、含修复入口）；`/flow repair` 从账本快照重建 status.json
  与台账成功（重建 1 个变更）。
  **后续修复（2026-10-31 第三轮，HEAD `4457386`）**：损坏的 status.json 不再被
  `listChanges` 静默跳过——`load()` 进入锁定模式、`/flow doctor` 单独列出损坏文件路径、
  `/flow repair` 从账本重建后解锁；上述「与 03 §14 不一致」的偏差已闭环（见
  [implementation-status.md](../impl/implementation-status.md) §3.8 与 §4 #10、`CHANGELOG.md`）。
- **账本行被截断（非签名篡改）**：`state/ledger.jsonl` 末行截断为非法 JSON → `load()` 不抛错、
  进入锁定模式；`doctor()` 报 `ledgerOk:false` 且**行号精确指向被截断行**、原因
  「不是合法的账本事件 JSON」；门禁内写入返回 `R-LOCKED` 拒绝、`newChange` 抛错拒绝；
  `repair()` 明确失败并报出行号，**不静默重写/截断坏账本**。
- **配置语义非法（未知 `levels.complexity` 值）**：`loadConfig` 抛 `ConfigError`，带配置路径与
  `levels.complexity` 字段名（语义错误无行号、语法错误才带行号）；宿主插件仍启动，引擎用默认
  配置降级并锁定，doctor 报 `configOk:false` 与修复入口，门禁写入 fail-closed（`R-LOCKED`）。

## 未能复验项及原因

| 项 | 状态 | 原因 |
|---|---|---|
| `--dump-config-schema` 退出码 0 | ⚠ 未能复验为通过（非 FlowGate host 行引入） | 本机 DSH 0.2.1-rc.5 上该命令返回 1，报 `error: [/…] unrecognized Loader tree carrier…`。归因实验：① **不带 FlowGate 的 web 基线 profile 同样失败**（4 处，全部来自宿主自带的 `@deepseek-ai/dsh-agent-preset` preset 行）；② 不带 FlowGate 的 headless 基线 profile 退出 0（无 preset 行）；③ 把本插件换成"只有 host 行、无 preset 行"的临时变体后，web 组合错误数仍为 4 处（与 web 基线完全一致）→ **host 行不引入该类错误**；④ 完整插件在 web 组合 7 处（= web 基线 4 + 本插件 3 个 preset 行各 1），在 headless 组合 3 处（= headless 基线 0 + 本插件 3 个 preset 行）。结论：这是 rc.5 schema 转储对「preset 行内嵌套 `plugins` 列表」的已知限制（宿主自带 preset 同样中招），**不能作为 host 入口 import 失败或成功的证据**；本轮以 `--dump-config` 组合树 + 脚本 7/7 作为兼容证据，并已把该偏差记入 host-integration.md §1。 |
| headless 真机 E2E（真模型 S0→S6、守卫拦截、审查） | ⏳ 本轮未复跑 | 需要真实模型 key 与联网，本环境无网络且不调用真实模型；本轮只复验离线组合/安装路径（headless 组合可导出，但完整插件下 `--dump-config-schema` 同受上述 preset 限制） |
| Desktop 端人工走查 | ⏳ 未自动化 | 需要人工在桌面会话操作（截至 2026-10-31 共 25 张截图，均为 Web 宿主，见 [../screenshots/README.md](../screenshots/README.md)） |
| UI 冷启动耗时 | ⏳ 未测 | 需要桌面端人工计时；本仓库不伪造该数字（见 startup.md 口径） |
