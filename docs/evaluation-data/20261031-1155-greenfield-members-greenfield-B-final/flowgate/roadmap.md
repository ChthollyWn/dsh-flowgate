# 路线图：会员管理系统 v1：可运行 + 登录

MVP 切线：**C0–C2**（C3 及以后不进 v1）。C0 必须是第一个变更：没有可跑的骨架，后面每个变更都无法验证。

| 变更 | 能力 | 一句话目标 | 验收要点 | 依赖 | 预计任务数 | MVP | 状态 |
|---|---|---|---|---|---|---|---|
| C0 | 工程骨架 | 空仓库变成能启动、能跑测试的最小 Node 工程 | `npm start` 后 `/healthz` 返回 200；`npm test` 跑通 1 个冒烟测试；README 有启动说明；无三方依赖 | — | 4 | 是 | 未开始 |
| C1 | 登录与会话 | 管理员能登录、退出，未登录被服务端挡回 | 正确密码 302 + HttpOnly Cookie；错误密码 401；无 Cookie 访问 `/members` 302 到 `/login`；退出后会话失效；密码以 scrypt 哈希落库 | C0 | 5 | 是 | 未开始 |
| C2 | 会员档案 | 登录后能看、搜、增、改、停用会员 | 列表分页 + 姓名/手机号搜索；新增校验必填与手机号唯一（409）；编辑生效；停用后列表标记；重启数据仍在 | C1 | 5 | 是 | 未开始 |
| C3 | 交付硬化 | 把 v1 变成可交接的版本 | 统一错误页/404；安全响应头；README 补数据文件、备份与重置说明；关键路径集成测试补齐 | C2 | 3 | 否 | 未开始 |
| C4 | 角色与权限 | 区分管理员/只读运营 | 角色表 + 路由级权限；越权用例 | C3 | 5 | 否 | 未开始 |
| C5 | 数据库迁移 | JSON 存储换 SQLite | 数据访问接口不变；迁移脚本；回归测试全绿 | C3 | 4 | 否 | 未开始 |

## 里程碑

- **M1 / v1（C0–C2）**：本机可启动、可登录、会员最小闭环、自动化测试全绿。达到即交付第一版。
- **M1.1（C3）**：可交接（错误处理、文档、集成测试）。
- **Backlog（C4–C5）**：等 v1 上线后有真实反馈再排，不提前开工。

## 排期原则

1. C0 不做完不碰业务代码，避免「边搭架子边改需求」。
2. 每个变更独立可验收、可回滚；C1 的鉴权用例是 C2 的前置门禁。
3. 需求扩张（会员自助注册、支付、多租户等）只进 Backlog，不塞进 C0–C2。
