# 项目级澄清：会员管理系统 v1：可运行 + 登录

## 目标用户与目标

- 主要用户：中小团队里负责会员运营的**管理员**（1–5 人），在电脑浏览器上使用。
- 场景：管理员打开系统，登录后查看会员名单、补充新会员、修正会员信息。
- 要解决的问题：现在会员信息散落在表格/聊天记录里；v1 先提供一个有登录保护、能落库的统一入口。
- 成功标准：新同事拿到仓库后，不改代码、不装三方依赖，10 分钟内能在本机启动并登录成功。

## 核心流程

1. 启动服务 → 控制台给出访问地址；首次启动创建/告知管理员账号。
2. 打开 `/login` → 输入用户名密码 → 成功进入 `/members`，失败留在登录页并提示。
3. 会员列表 → 搜索姓名/手机号 → 新增或编辑会员 → 保存后列表立即可见。
4. 退出登录 → 会话失效，再访问 `/members` 被重定向回 `/login`。
5. 进程重启 → 会员数据与账号仍在，已登录会话按持久化策略恢复或要求重新登录。

## MVP 边界（做 / 不做）

**做：**

- 一条命令本机启动（`npm start`），浏览器可访问，`GET /healthz` 可用于探活。
- 管理员用户名 + 密码登录、退出、会话保持；未登录访问业务页由**服务端**挡回登录页。
- 会员最小闭环：列表、按姓名/手机号搜索、新增、编辑、停用/启用。字段：姓名、手机号、等级、状态、备注。
- 密码加盐哈希存储；会话 Cookie 为 `HttpOnly` + `SameSite=Lax`。
- 数据落本地文件，重启不丢；原子写避免半截文件。
- `node --test` 自动化测试覆盖登录成功/失败、未授权访问、会员新增与重复手机号、持久化。
- README 写清启动、初始账号、测试、数据文件位置。

**不做：**

- 会员自助注册、会员端登录、找回密码、短信/邮箱验证码。
- 多角色权限矩阵、多租户、组织架构、审计日志。
- 支付、订单、积分、营销、导入导出、报表、消息通知。
- 第三方登录（微信/钉钉/OAuth）、SSO。
- 生产部署（容器、HTTPS、反向代理、备份恢复、可观测性）；v1 只保证本机可跑。
- 前端框架/SPA/视觉设计稿；用服务端渲染 + 少量原生 JS，移动端可读即可。

## 技术栈与部署

- 运行时：Node.js ≥ 18（使用内置 `node:http`、`node:crypto`、`node:test`）。
- 依赖：**零运行时依赖、零开发依赖**。理由：空仓库、无法保证联网安装；零依赖最可能「拉下来就能跑」。若团队强制其他栈，只换实现，不改变本文件的范围与验收。
- 存储：`data/db.json`，进程内串行写 + 临时文件 `rename` 原子替换；数据访问封装在 `src/store.js`，后续可替换为 SQLite/Postgres。
- 密码：`crypto.scrypt` 加盐哈希；比较用 `crypto.timingSafeEqual`。
- 会话：32 字节随机令牌，`HttpOnly`、`SameSite=Lax`、`Path=/`；服务端存令牌哈希与过期时间，落盘以便重启恢复。
- 前端：`public/` 下静态 HTML/CSS/JS，服务端渲染列表；所有动态输出做 HTML 转义。
- 部署：单机单进程，`npm start`（`node src/server.js`），默认 `127.0.0.1:3000`，`PORT` 可覆盖；`npm test` 跑 `node --test`。

## 非功能要求

- 安全：默认拒绝——除 `/login`、静态资源、`/api/auth/login`、`/healthz` 外全部要求有效会话；请求体上限 64KB；静态文件路径规范化并限制在 `public/` 内；不记录明文密码/令牌。
- 性能：v1 目标 ≤ 1 万会员；列表分页（每页 20），搜索为服务端过滤；单次页面响应本机 < 200ms。
- 可靠性：数据文件损坏时拒绝启动并给出明确提示，不静默清空；写失败返回 5xx 且不破坏原文件。
- 可维护性：路由/存储/鉴权分层，单文件职责清晰；关键决策写进 README。
- 合规：仅存业务必要字段；手机号在列表中默认脱敏展示（编辑页可见完整值）。

## 约束与未知项

- 约束：仓库当前为空；不能假设可联网安装依赖；无既有 CI/部署环境；v1 时间盒按 3 个变更（C0–C2）控制。
- 未知项（需负责人在 GR 确认，未回复则按默认执行）：
  1. 技术栈用 Node.js 零依赖是否可接受？（默认：接受）
  2. v1 是否必须含「会员新增/编辑」，还是只做登录 + 只读列表？（默认：含最小新增/编辑）
  3. 初始管理员账号：环境变量 `ADMIN_USER`/`ADMIN_PASSWORD` 种子，未设置则随机生成并打印一次？（默认：是）
  4. 数据落 JSON 文件是否可接受，还是 v1 就必须上数据库？（默认：JSON 文件）
  5. 是否需要中文界面？（默认：是，界面文案中文）
- 风险提示：本需求含「登录」，FlowGate 判定为高风险信号；实现阶段需把鉴权用例作为必过门禁，而不是只做页面。
