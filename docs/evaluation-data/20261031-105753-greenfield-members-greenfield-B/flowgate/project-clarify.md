# 项目级澄清：会员管理系统 v1（可运行 + 登录）

## 目标用户与目标

**原始需求：** "我们要做一个会员管理系统，第一版能跑起来、能登录就行。"

仓库起点为空（无代码、无构建、无测试），需求只有一句话。本文件把它收敛为可执行、可验收的范围。

| 角色 | 场景 | v1 是否覆盖 |
| --- | --- | --- |
| 管理员 | 用初始账号登录后台，查看/新增会员 | ✅ |
| 管理员 | 登出，会话立即失效 | ✅ |
| 会员本人 | 自助注册、查看自己的积分/等级 | ❌ 后续 |
| 运营 | 积分规则、等级体系、营销 | ❌ 后续 |

**v1 目标：**
1. **能跑起来**：干净环境一条命令启动，浏览器可访问。
2. **能登录**：正确的用户名/密码可登录，状态可持续，可登出；错误凭据被拒绝。
3. **像个会员系统**：登录后能看到会员列表，至少能新增一个会员。

## 核心流程

1. **首次启动**：建库建表 → 无管理员则创建初始管理员（用户名/密码来自环境变量；缺省生成一次性随机密码并打印到启动日志，避免仓库硬编码弱口令）。
2. **登录**：校验用户名密码 → 生成随机 token 写 `sessions` → Set-Cookie（HttpOnly, SameSite=Lax）→ 302 到会员列表。
3. **鉴权**：受保护路径读 Cookie → 查 session 且未过期 → 放行，否则 302 登录页。
4. **登出**：删除 session 记录 + 清 Cookie。
5. **新增会员**：校验必填/手机号格式/唯一性 → 入库 → 回列表并提示成功。

## MVP 边界（做 / 不做）

**做：**
- 账号登录 / 登出（服务端会话）
- 初始管理员初始化（seed）
- 未登录访问受保护页 → 跳转登录页
- 会员列表（v1 全量，不分页）
- 新增会员（姓名、手机号、等级）
- 健康检查端点 `/healthz`
- 单元测试 + 主链路冒烟测试，一条命令可跑

**不做：**
- 会员自助注册、找回密码、短信/邮箱验证
- 角色权限细分（v1 只有 admin）
- 积分规则引擎、等级自动升级、储值/支付
- 导入导出、报表
- 多租户、生产部署、HTTPS 证书、第三方登录（OAuth/微信）

## 技术栈与部署

| 维度 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3（仅标准库） | 零第三方依赖即可跑，排除「环境没装对」这类首版失败原因 |
| Web | `http.server`/WSGI 极简封装 | 路由少，不引入框架依赖 |
| 存储 | SQLite（`sqlite3`） | 单文件、零运维，适合 v1 与本地演示 |
| 页面 | 标准库字符串模板 + 少量 HTML | 不引入前端构建链 |
| 密码 | `hashlib.scrypt` + 随机 salt | 标准库内存硬哈希，避免明文/弱哈希 |
| 会话 | 服务端 `sessions` 表 + HttpOnly Cookie | 可服务端失效，优于纯 JWT（v1 需登出即失效） |
| 测试 | `unittest` | 标准库，零安装 |
| 部署 | 本地 `python3 -m app`（默认 8000） | v1 只要求本地可跑，不做云部署 |

数据模型：
- `users`：`id`, `username`(唯一), `password_hash`, `salt`, `role`, `status`, `created_at`
- `sessions`：`token`(主键), `user_id`, `expires_at`, `created_at`
- `members`：`id`, `name`, `phone`(唯一), `level`, `status`, `created_at`

选型原则：**先能跑，再谈架构**。功能膨胀后可平滑迁移 FastAPI/Django，存储 SQLite → PostgreSQL。

## 非功能要求

- **安全（登录属高风险面）**：密码只存 scrypt 哈希；Cookie HttpOnly + SameSite=Lax；session 有过期时间；登录失败提示不区分「用户不存在/密码错误」；初始口令不落仓库。
- **可用性**：`python3 -m app` 一条命令启动；`/healthz` 供冒烟检查。
- **可维护性**：分层（路由 / 业务 / 存储），核心逻辑有 `unittest` 覆盖。
- **性能**：v1 单实例、单进程、SQLite，目标 ≤ 50 并发用户，不支持写入高峰。

## 约束与未知项

**约束**
- 当前环境沙箱不可用，shell 命令受限；验证以 `flow_verify` 插件的执行回执为准。
- v1 单实例部署，不做水平扩展。

**未知项 / 默认假设（负责人可推翻）**

| 项 | 默认假设 | 若推翻的影响 |
| --- | --- | --- |
| 交付形态 | 本地可运行 Web 应用，非云部署 | 若需上线，追加部署变更与 HTTPS |
| 技术栈 | Python 3 标准库 + SQLite | 若团队要求 Node/Java，C0 需重做 |
| 初始账号 | 环境变量注入，缺省随机密码打印日志 | 若要求固定演示账号，改为显式配置 |
| 会员字段 | 姓名 / 手机号 / 等级 | 后续按业务补充，需迁移 |
| 自助注册 | 不做，仅管理员创建 | 若要做，需加注册流程与防滥用 |

## 验收标准（v1 Done 的定义）

- [ ] `python3 -m app` 在干净环境启动成功，日志给出访问地址。
- [ ] `GET /healthz` 返回 200 与 `ok`。
- [ ] 未登录访问 `/members` → 302 到 `/login`。
- [ ] 正确账号密码登录 → 302 到 `/members`，页面含会员列表。
- [ ] 错误密码 → 停留登录页并提示错误，不建立会话。
- [ ] 登录后可新增会员，列表可见；重复手机号被拒绝。
- [ ] 登出后原 Cookie 再访问 `/members` → 302 到 `/login`。
- [ ] `python3 -m unittest` 全绿（覆盖上述主链路）。
- [ ] README 含「安装 / 启动 / 初始账号 / 测试」四节。
