# 路线图：会员管理系统 v1（可运行 + 登录）

MVP 切线：C0–C3 在 v1 切线内；C4 起为后续演进，不在第一版承诺。

| 变更 | 能力 | 一句话目标 | 验收要点 | 依赖 | 预计任务数 | MVP | 状态 |
|---|---|---|---|---|---|---|---|
| C0 | 工程骨架 | 空仓库变成能启动、能跑测试的最小工程 | `python3 -m app` 起服务返回 200；`python3 -m unittest` 跑通 1 个冒烟测试；README 有启动说明 | — | 5 | 是 | 未开始 |
| C1 | 账号登录闭环 | 管理员能登录、登出，未登录被拦截 | 正确凭据登录成功且建会话；错误凭据被拒；登出后会话失效；`/members` 未登录 302 到 `/login`；密码只存 scrypt 哈希 | C0 | 6 | 是 | 未开始 |
| C2 | 会员基础管理 | 登录后能看会员列表并新增会员 | 列表展示已有会员；新增成功后列表可见；手机号重复/格式非法被拒；数据落 SQLite | C1 | 5 | 是 | 未开始 |
| C3 | 可运行交付与冒烟 | 一键初始化 + 冒烟验证，交付说明齐全 | 初始化脚本可用；端到端冒烟脚本跑通「启动→登录→新增→登出」；README 含安装/启动/初始账号/测试 | C1, C2 | 3 | 是 | 未开始 |
| C4 | 会员自助与账号安全 | 会员自助查看、改密、登录限流 | 改密、登录失败限流、会话刷新 | C1 | 5 | 否 | 未开始 |
| C5 | 等级与积分 | 等级体系与积分规则可配置 | 等级配置、积分流水、自动升级 | C2 | 6 | 否 | 未开始 |

## 说明

- **C0 必须是第一个变更**：先把「构建 / 启动 / 测试」的骨架立起来，后续每个变更才有地方落代码、有测试可加。
- C1 是需求里的硬指标（"能登录"），因此优先于会员业务功能；C2 让系统"像会员系统"。
- C3 把「能跑起来」固化为可重复的冒烟流程，避免只在开发机上偶然跑通。
- C4/C5 不在第一版承诺内，列出来是为了让 v1 的边界可被明确说「不」。

## 首个变更（C0）任务预估

1. 目录结构与包初始化（`app/`、`tests/`）。
2. 配置项（端口、数据库路径、初始管理员环境变量）与默认值。
3. 最小 HTTP 服务 + `/healthz`。
4. `unittest` 冒烟测试 + 测试运行入口。
5. README 启动说明。
