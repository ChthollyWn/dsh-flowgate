# 项目级澄清：会员管理系统（首版）

## 目标用户与目标

- **用户**：单人/小团队的会员管理员。
- **场景**：管理员在浏览器打开系统，用预置账号登录后查看会员管理首页。
- **目标**：从空仓库交付一个可本地启动的会员管理系统首版，唯一硬指标是“服务能跑起来、管理员能登录并进入受保护页面”。

## 核心流程

1. 执行 `npm start` 启动服务。
2. 浏览器访问首页，未登录时跳转到 `/login`。
3. 管理员输入用户名和密码。
4. 校验成功：创建服务端会话，跳转受保护首页；校验失败：停留在登录页并显示统一错误提示。
5. 首页显示当前管理员和只读会员列表。
6. 点击退出：销毁会话，再次访问首页需重新登录。

## MVP 边界（做 / 不做）

- 做：一条命令启动的 Node.js Web 服务与 `/health` 健康检查；预置管理员账号（scrypt 加盐哈希）；登录页、登录失败提示、服务端会话、退出登录；未登录访问受保护首页时重定向到登录页；登录后的只读会员列表（示例数据）；登录闭环的自动化测试与 README。
- 不做：会员自助注册、找回密码、短信/邮箱验证码、第三方登录；多角色、细粒度权限、多租户；会员新增/编辑/删除（首版列表只读）；支付、订单、续费、积分、优惠券；生产级数据库、缓存、消息队列、容器编排。

## 技术栈与部署

- **运行时**：Node.js 20+，仅使用标准库，无第三方运行时依赖。
- **HTTP**：原生 `node:http`，服务端渲染 HTML。
- **存储**：仓库内 JSON 示例数据；首版只读，启动时载入内存。
- **会话**：随机 ID + 服务端内存会话表；Cookie 使用 `HttpOnly`、`SameSite=Lax`，默认 8 小时过期。
- **测试**：Node 内置 `node:test`，通过真实 HTTP 请求验证登录闭环。
- **部署**：本地或内网单进程运行，默认端口 3000，可用 `PORT` 覆盖；不承诺公网生产级部署。

## 非功能要求

- **安全基线**：密码不存明文；会话 Cookie 不可被前端脚本读取；登录失败不区分“账号不存在/密码错误”；提交内容做 HTML 转义。
- **可用性**：空环境无需安装第三方包即可启动；启动失败有清晰日志。
- **性能**：首版单进程、低并发，页面响应在本地环境可忽略延迟。
- **兼容性**：Node.js 20+；现代浏览器。
- **可维护性**：路由、认证、数据访问分层；测试可重复执行。

## 约束与未知项

- **已知约束**：当前仓库为空；首版不引入构建链和外部数据库，优先保证可运行。
- **默认假设**：单管理员、单租户；管理员预置，不开放注册；会员列表只读；默认账号 `admin`，密码可用 `ADMIN_PASSWORD` 覆盖。
- **待负责人确认**：是否需要首版就支持会员增删改、是否需要多角色、是否有指定技术栈或部署环境。未确认前按上述默认假设推进，避免范围蔓延。
