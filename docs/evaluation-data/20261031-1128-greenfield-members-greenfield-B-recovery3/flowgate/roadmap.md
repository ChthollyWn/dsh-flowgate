# 路线图：会员管理系统 MVP：可运行、可登录

MVP 切线：C0–C1。先建立可启动、可测试的工程骨架，再完成唯一的硬需求“能登录”；会员 CRUD 与权限体系留到首版之后。

| 变更 | 能力 | 一句话目标 | 验收要点 | 依赖 | 预计任务数 | MVP | 状态 |
|---|---|---|---|---|---|---|---|
| C0 | 工程骨架 | 能启动、能跑测试、有运行文档 | `npm start` 启动服务，`/health` 正常；`npm test` 通过骨架测试；README 与目录结构可用 | — | 4 | 是 | 未开始 |
| C1 | 管理员登录 | 完成登录、会话与受保护首页闭环 | 正确/错误密码、未登录拦截、退出失效均有自动化测试；首页显示管理员与只读会员列表 | C0 | 6 | 是 | 未开始 |
| C2 | 会员资料维护 | 支持会员新增、编辑、停用与字段校验 | CRUD、校验、审计字段；不纳入首版 | C1 | 6 | 否 | 后续 |
| C3 | 角色与审计 | 区分管理员角色并记录关键操作 | 权限矩阵、审计日志；不纳入首版 | C2 | 6 | 否 | 后续 |

## C0 工程骨架（第一个变更）

- 建立 `package.json`、`src/`、`test/`、`.gitignore`。
- 使用 Node 标准库启动 HTTP 服务，提供 `/health`。
- 建立统一响应与基础安全响应头。
- 用 `node:test` 写一个可通过的骨架测试。
- 补齐 README 的启动、测试、目录说明。

## C1 登录闭环

- 预置管理员与 scrypt 密码哈希。
- `GET /login` 登录页；`POST /login` 校验并创建会话。
- `GET /` 受保护首页；未登录 302 到 `/login`。
- `POST /logout` 销毁会话并清 Cookie。
- 登录失败统一提示，避免账号枚举。
- 测试覆盖成功、失败、未登录拦截、退出登录。

## 首版完成定义

C0 与 C1 均通过各自门禁；在干净环境执行 `npm start` 能打开登录页并完成一次真实登录；`npm test` 全绿；README 与实际行为一致。
