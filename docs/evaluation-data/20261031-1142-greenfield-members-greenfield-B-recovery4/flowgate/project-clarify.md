# 项目级澄清：会员管理系统 v1：可运行 + 登录

## 目标用户与目标

- **业务管理员**：在本地或内网打开系统，用账号登录后查看会员基础信息。
- **项目开发者**：在空仓库中按 README 一条命令启动应用并跑通自动化测试。

目标是交付一个最小可用的会员管理系统 v1：默认可启动、可登录、登录后能看到会员列表，为后续增删改和权限能力提供可运行基线。

## 核心流程

1. 启动服务，浏览器打开登录页。
2. 输入预置管理员账号与密码。
3. 登录成功后进入受保护页面，查看会员列表（姓名、手机号、等级、加入时间）。
4. 刷新页面保持登录；点击退出后会话失效并回到登录页。
5. 未登录直接访问受保护页面时跳转到登录页。

## MVP 边界（做 / 不做）

**做：**

- 可本地启动的 Web 应用，提供 `/health` 健康检查。
- 登录页、登录接口、退出接口、服务端会话（HttpOnly Cookie）。
- 未登录访问受保护资源时跳转登录页/返回 401。
- 预置管理员账号（scrypt 加盐哈希，支持环境变量覆盖）。
- 登录后的只读会员列表（预置数据）。
- 自动化测试：健康检查、登录成功、密码错误、未登录拦截、退出后失效。
- README：环境要求、启动、测试、默认账号与安全提示。

**不做：**

- 会员新增、编辑、删除；用户注册、找回密码、验证码。
- 多角色权限、多租户、审计日志、在线支付、积分营销。
- 外部数据库、生产级部署、HTTPS、容器编排。

## 技术栈与部署

- **运行时**：Node.js 20+，仅使用标准库（`http`、`crypto`、`fs`、`node:test`），零第三方运行时依赖。
- **前端**：原生 HTML/CSS/JavaScript，由同一个 Node 服务提供静态文件。
- **数据**：仓库内 JSON 文件保存管理员与预置会员，启动时自动初始化；v1 会员数据只读。
- **会话**：服务端内存会话 + 随机 Session ID 的 HttpOnly Cookie；重启后需重新登录（v1 可接受）。
- **部署**：本地/单实例启动，`npm start` 即可；不依赖数据库或云服务。

## 非功能要求

- **安全**：密码不明文存储，使用 scrypt 加盐哈希；登录失败统一提示；Cookie 设置 HttpOnly、SameSite=Lax；默认账号仅限本地开发并在文档中显著提示。
- **可用性**：默认配置无需额外环境变量即可启动；错误输入有明确提示；核心页面在常见桌面浏览器可用。
- **性能**：单实例、小数据量，接口在本机毫秒级响应；不引入不必要的构建步骤。
- **可维护性**：服务端按配置、认证、路由、存储拆分模块；测试覆盖核心登录路径；无第三方依赖降低供应链与安装风险。

## 约束与未知项

- v1 为单实例、本地/内网使用；内存会话在重启后失效。
- JSON 文件存储不适合高并发写入；v1 会员数据只读，后续写操作前迁移数据库。
- 复杂度建议 medium，风险 high（涉及登录鉴权），需负责人确认。
- 默认管理员凭据的具体值在 C1 实现时写入 README；生产使用前必须通过环境变量覆盖。
